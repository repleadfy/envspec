# Plano 2: envpact 0.2 — fonte OpenBao, `pull`/`run`/`push`/`set`, tokens cifrados e agente

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O envpact passa a falar com o OpenBao (KV v2). Ele baixa segredos validados para um `.env` 0600 (`pull`) ou só para o processo (`run`), e grava segredos validados com confirmação humana (`push`/`set`). Os tokens ficam em `~/.ob_read`/`~/.ob_write` cifrados com senha, e um agente local guarda o token de leitura por uma janela.

**Architecture:**
- O contrato ganha a seção `[source]`, que diz onde estão os segredos de cada env, e o tipo `url(schemes)`.
- Um cliente KV v2 em Net::HTTP, `EnvPact::OpenBao::Client`, é a única peça que fala HTTP.
- As credenciais são resolvidas assim:
  - leitura: agente → `~/.ob_read` + senha;
  - escrita: sempre `~/.ob_write` + senha, sem agente.
- O login é OIDC por loopback (como o `bao login -method=oidc`), ou o token vem pelo stdin (plano B).
- Os comandos novos seguem o padrão `EnvPact::CLI::Command` e reaproveitam `check`/`Dotenv`/`exec`.

**Tech Stack:** Ruby ≥ 2.5, só stdlib (`net/http`, `openssl`, `json`, `socket`, `io/console`; `pty` só nos testes), minitest.

**Spec:**
- Repo `repleadfy/k8s-openbao` (`~/leadfy/code/k8s-openbao`), que substituiu a pasta `leadfy_infra/…/openbao`:
  - `DESENHO.md` (desenho fechado, 22/11);
  - `revisao/envspec-0.1.2.md`, seção "O que falta para o desenho";
  - `aplicar/04-bootstrap/README.md` e `policies/` (mounts, roles, policies e TTLs reais do servidor, aplicados em 22/11).
- **Convenção de caminhos no KV `secret/`** (Tom, 22/11): `cluster/<ns>/<deploy>` (segredos de deploy, lidos pelo ESO), `team/<ferramenta>` (do time, Tom e Lucas) e `tools-<pasta>/<ferramenta>` (pessoal; `<pasta>` é o metadado `pasta` da entidade, por exemplo `tools-tom/`). As policies são `cluster-*`, `team-*` e `tools-pessoal-*`. Os nomes antigos `ferramentas-time`/`ferramentas-tom` não existem no servidor.
- A base do código é o envpact 0.1.0: `docs/superpowers/specs/2026-10-25-envpact-redesign-design.md`.

## Decisões deste plano (minhas; revisar)

- **Virada de escopo:** o 0.1.0 tinha como anti-goals "envpact não grava em disco" e "não faz sync". O DESENHO de 22/11 reverte as duas coisas. Agora o envpact grava só `~/.ob_read`, `~/.ob_write` e o alvo do `pull`, sempre em 0600, e só fala com o OpenBao. README e CHANGELOG registram isso.
- **A fonte guarda só `[secrets]`.** `pull`/`run`/`check --source` leem só as chaves secretas do env. `push`/`set` gravam só chaves secretas. O ConfigMap continua vindo de `.env*` versionados, `app.yml` e defaults.
- **`pull` grava em `.env.<env>.local` por padrão** (`--out=PATH`). Esse arquivo já é o último lido pelo `check`, então os segredos baixados ganham dos outros arquivos. Ao juntar valores para validar, o `pull` não lê o próprio alvo.
- **`run`:** a fonte sobrescreve o ENV do processo, como no `infisical run`. Depois valida (`extras: false`), preenche os defaults e faz `exec`. O token nunca entra no ENV do filho.
- **`push` e `set` fazem merge (PATCH) e nunca apagam chave.** Na primeira gravação o caminho não existe (404), e aí o envpact faz POST. Isso basta para o `cluster-escrita`, que tem create/update/patch e não tem read.
- **Login:** `envpact login --read|--write [--role=NAME] [--oidc-mount=oidc] [--port=8250] [--token-stdin]`.
  - Sem `--role`, o `--read` usa o `default_role` do servidor (`leitura`), e o `--write` exige `--role`.
  - A skill da Leadfy documenta `--write --role=escrita`.
- **O nome da flag do `unlock` é `--for=DURATION` (default `2h`)**, com o alias `--por`. A CLI é em inglês, mas o DESENHO usa `--por`.
- **Nenhuma env var nem flag fornece senha, token de escrita ou confirmação.** A senha e o "y" vêm só de `/dev/tty`. Os testes usam PTY ou injetam um prompt na biblioteca.

## Global Constraints

- Só stdlib, sem dependência de runtime. As de desenvolvimento têm teto (Task 1, Step 0). Sintaxe Ruby 2.5: sem `Hash#except`, pattern matching, endless method nem `filter_map`.
- **Nenhum valor de segredo nem token** em stdout, stderr, mensagem de exceção, `inspect`, argv ou ENV de processo filho. Isso vale também para o `--show-values`: ele só existe no `check` local, e o `check --source` o recusa.
- Arquivos que o envpact grava: `~/.ob_read`, `~/.ob_write` e o alvo do `pull`. Os três são criados já em 0600 (`File::CREAT|File::EXCL`, modo 0600), num temporário do mesmo diretório seguido de `rename`. O envpact recusa gravar através de symlink.
- Token de escrita: nunca vai para o agente nem para cache, e é decifrado a cada `push`/`set`.
- `push`/`set` sem TTY: recusam **antes** de qualquer chamada de rede, com exit 1 e `needs a terminal to confirm writes`.
- Exit codes do 0.1.0: 0 ok, 1 falha de contrato/rede/credencial, 2 uso, 126/127 no `run` como no `exec`.
- OpenBao: só KV v2. `mount` default `secret`. O endereço vem de `addr=` no `[source]` ou de `$BAO_ADDR`. Cabeçalho `X-Vault-Token`. TLS verificado (Net::HTTP default). Timeout de 10s.
- Cifra dos `~/.ob_*`: AES-256-GCM. A chave sai de PBKDF2-HMAC-SHA256 com 600 000 iterações e salt de 16 bytes. Formato JSON `v: 1`.
- Mensagens e CLI em inglês, comentários em inglês (padrão do repo). Este plano é em português.
- O `rake test` roda com UTF-8 forçado no processo de teste (`-EUTF-8`), seja qual for o `LANG` da máquina ou da imagem. Os testes de C locale do `test_encoding.rb` continuam limpando o próprio ambiente do subprocesso e seguem valendo.

## Review Focus

1. **`~/.ob_*` com permissão frouxa** (por exemplo 0644 depois de um `cp`): recusa usar, como o ssh, com `chmod 600 ~/.ob_read`. Teste na Task 4.
2. **Socket do agente órfão** depois de crash ou kill -9: o `unlock` seguinte substitui o socket morto, e os clientes tratam ECONNREFUSED/ENOENT como "sem agente". Conexão de outro uid é recusada. Testes na Task 6.
3. **Token vencido ou revogado:** o OpenBao responde 403 (`permission denied`/`invalid token`). A mensagem diz `token rejected for secret/<path> (expired, revoked or not allowed); run envpact login --read`, sem stack trace e sem o token. Teste na Task 3.
4. **Ida e volta de valor com `\n`, `"`, `\`, `#` e espaço no fim** entre `pull` e `Dotenv.parse`: o valor tem que voltar idêntico. Teste na Task 7.
5. **Gravação sem humano** (Claude Code, CI, stdin redirecionado) no `push`/`set`: nenhuma requisição chega ao servidor. O fake registra zero PATCH/POST. Teste na Task 9.

### Task 2: Seção `[source]` no contrato

**Files:**

**Sintaxe:**
```
[source]
openbao path=team/promptune/{env}
openbao path=cluster/selly/promptune-web env=production
```
- Uma linha por fonte: `openbao` seguido de pares `k=v` separados por espaço. As chaves são `path` (obrigatória), `mount` (default `secret`), `addr` e `env` (lista separada por vírgula).
- A linha sem `env=` é o fallback. Uma linha com `env=` ganha do fallback para aqueles envs.
- `{env}` é o único placeholder. O path só aceita `[A-Za-z0-9_./{}-]`, sem `..` e sem `/` no começo.
- Dentro de `[source]` só valem linhas `openbao …`. O próximo header (`[env:]`, `[shared]`, `[secrets]`) sai do bloco com as regras de sempre. Um `[secrets]` logo depois de `[source]` não tem escopo anterior a herdar e volta ao shared.

### Task 5: `envpact login`

**Files:**
- Create: `lib/envpact/oidc_login.rb` (`EnvPact::OIDCLogin`), `lib/envpact/cli/login.rb`
- Modify: `lib/envpact/cli.rb` (`COMMANDS`)
- Test: `test/test_oidc_login.rb`, `test/test_cli_login.rb`

**Uso:** `envpact login --read|--write [--addr=URL] [--role=NAME] [--oidc-mount=oidc] [--port=8250] [--token-stdin]`. O `addr` vem de `--addr`, depois de `$BAO_ADDR`, depois do `[source]` do `./env.spec`, se houver.

**Interfaces:**
- Consumes: `OpenBao::Client` (Task 3), `Keyfile`, `Prompt` (Task 4).
- Produces: `OIDCLogin.new(client:, mount:, role:, port:, opener:).token -> String`.
  1. Faz bind em `127.0.0.1:<port>`; com `port: 0`, usa a porta real. `redirect_uri = "http://localhost:<port>/oidc/callback"`.
  2. POST `auth/<mount>/oidc/auth_url` com `{role, redirect_uri, client_nonce}` → `data.auth_url`.
  3. `opener.call(url)`. O default tenta `open`/`xdg-open`/`wslview` e **sempre** imprime a URL em stderr.
  4. Espera um GET `/oidc/callback?code&state` por até 120s. Responde ao navegador com uma página de texto `envpact: login ok, you can close this tab`.
  5. GET `auth/<mount>/oidc/callback?state&code&client_nonce` → `auth.client_token`.
- Fluxo da CLI:
  - obtém o token (OIDC, ou `--token-stdin`, que lê uma linha do stdin);
  - faz `lookup_self` para confirmar o token e pegar o `expire_time`;
  - pede a senha nova duas vezes pelo `Prompt` e recusa se diferirem ou tiverem menos de 12 caracteres;
  - grava com `Keyfile.write`;
  - imprime `✓ logged in (read, role leitura, expires 2026-11-23 03:00) → ~/.ob_read`.
- `--write` sem `--role` e sem `--token-stdin` → UsageError `--write needs --role=NAME`.

### Task 6: Agente — `unlock`, `lock`, `status` e resolução de credenciais

**Files:**

**Interfaces:**
- Produces:
  - `Agent.socket_path`: `$ENVPACT_AGENT_SOCK`, ou `File.join(ENV["XDG_RUNTIME_DIR"] || Dir.tmpdir, "envpact-#{Process.uid}", "agent.sock")`. O diretório é criado em 0700. Se ele existir com dono ou modo errado → Error.
  - `Agent.start(token:, addr:, until_time:)`: faz `fork` + `Process.setsid`. O filho apaga um socket morto e faz bind 0600 (umask 0o177 durante o bind). Ele atende até `until_time`, até um `lock` ou até 8h no máximo, e então remove o socket e sai. O pai espera o socket aceitar conexão (até 2s) e retorna o pid. Um agente vivo é substituído: `lock` e depois `start`.
  - Protocolo: uma linha JSON por conexão.
    - `{"op":"token"}` → `{"token":…, "addr":…, "until":…}`;
    - `{"op":"status"}` → `{"addr":…, "until":…}`, sem token;
    - `{"op":"lock"}` → `{"ok":true}`, e o agente sai.
    - O servidor recusa um peer com uid diferente (`getpeereid`).
  - `Agent.request(op) -> Hash | nil`: nil quando o socket não existe ou recusa a conexão.
  - `Credentials.new(prompt:).read_token -> {token:, addr:}`: tenta o agente; senão `Keyfile.read(:read, passphrase: prompt.secret("Passphrase for ~/.ob_read: "))`.
  - `Credentials.new(prompt:).write_token -> {token:, addr:}`: sempre o Keyfile `:write` mais a senha, nunca o agente.
  - CLI:
    - `envpact unlock [--for=2h|--por=2h]` aceita `\d+[smh]`, com teto de 8h e do `expire_time` do arquivo. Faz `renew_self` antes de subir o agente.
    - `envpact lock` → exit 0 mesmo sem agente.
    - `envpact status` imprime, sem segredo, o estado do agente (até quando) e de cada `~/.ob_*` (role, expira em).

  - `Dotenv.dump(hash) -> String`: uma linha `KEY="…"` por chave, em ordem alfabética. Escapa `\` → `\\`, `"` → `\"` e newline → `\n`, de modo que `Dotenv.parse(dump(h)) == h` para qualquer valor sem `\r`. Um valor com `\r` → Error naming the key.
  - `envpact pull --env=NAME [--out=PATH] [--spec=PATH]`:
    1. Busca a fonte e junta `Dotenv.load` (sem o arquivo alvo) com os valores da fonte.
    2. Roda `check` (`strict: false`). Com erro, não grava, mostra o report e sai com exit 1.
    3. Grava `AtomicFile.write(out, "# written by envpact pull from openbao:<mount>/<path> at <iso8601>; do not edit\n" + dump)`.
    4. Imprime `✓ pulled 4 secrets → .env.development.local (0600)`.
    5. Se `git check-ignore -q <out>` sair com 1 (o arquivo não está ignorado), avisa `! <out> is not git-ignored`. Sem git, não avisa.
  - `envpact check --source …`: igual ao `check` de arquivos, mas a fonte sobrescreve em memória. `--source` com `--show-values` → UsageError. `--source` com `--from-env` é aceito.
